# libSceLibreSsl3

## add Functional

- [X509_STORE_load_locations lengths](../../../core/libs/prx/libSceLibreSsl3/src/X509StoreLoadLocations.cpp) (libSceLibreSsl3) - an indefinite-length element is delimited by its end-of-contents before its fields are decoded, so the first reason can differ from `tasn_dec.c` of the pinned 078b3d1d LibreSSL, which decodes as it reads: elements left before that end fail with 148, 168 or their own header error (123, 155) where LibreSSL fails with 137, a header error inside the element is reported before an error in an earlier field, and input that ends before the end-of-contents fails with 137 where LibreSSL can first report the error of the element it reads past the end (123, 168 or 121). Only the first reason is queued, without the 102 that LibreSSL adds after a header error or its nested 58, PEM 13 and X509 9 reasons. Not compared with the console.
- [X509_STORE_load_locations constructed and primitive forms](../../../core/libs/prx/libSceLibreSsl3/src/X509StoreLoadLocations.cpp) (libSceLibreSsl3) - outside a name value and the auxiliary data, a primitive type written in constructed form (INTEGER, BOOLEAN, NULL, OBJECT IDENTIFIER, UTCTime, GeneralizedTime, OCTET STRING, BIT STRING) fails with 168 (148 for a unique identifier; an algorithm parameter throws), and a SEQUENCE OF or SET OF written in primitive form (extensions, name, RDN) fails with 149 or 168, where the pinned 078b3d1d LibreSSL joins the segments as `asn1_collect` does, or reads the items, and loads the certificate. Not compared with the console.
- [X509_STORE_load_locations tbsCertificate tail](../../../core/libs/prx/libSceLibreSsl3/src/X509StoreLoadLocations.cpp) (libSceLibreSsl3) - after the subject public key, an element other than a unique identifier (`81`, `82`) or `[3]`, an end-of-contents and an element with a header error all fail with 148, where the pinned 078b3d1d LibreSSL reads the header of each optional field and fails with 168 (another tag), 159 (an end-of-contents in a definite tbsCertificate) or its own header error (123, 155). Not compared with the console.
- [X509_STORE_load_locations auxiliary data](../../../core/libs/prx/libSceLibreSsl3/src/X509StoreLoadLocations.cpp) (libSceLibreSsl3) - placement not measured on the console: the `X509_CERT_AUX` decoded from the bytes after the certificate in a hashed directory file or a `TRUSTED CERTIFICATE` record is stored at offset 208 of the 216-byte certificate, where `aux` is in the LibreSSL 4.0.0 [`x509_local.h`](https://github.com/libressl/openbsd/blob/ce488b78e0bd994780569df718596b9776ff681a/src/lib/libcrypto/x509/x509_local.h#L181-L206) layout this library declares for `X509`; the pinned 078b3d1d LibreSSL, whose `x_x509a.c` decoding is followed, has `aux` at offset 168 of a 176-byte `X509`. No export of this library reads or releases it yet.
- [X509_STORE_load_locations algorithm parameters](../../../core/libs/prx/libSceLibreSsl3/src/X509StoreLoadLocations.cpp) (libSceLibreSsl3) - an algorithm parameter, in the certificate or in `other` of its auxiliary data, that is not a NULL, INTEGER, BIT STRING, OCTET STRING, OBJECT IDENTIFIER or one of the string types of `X509_NAME` values throws, constructed or not and with any tag number, where the pinned 078b3d1d LibreSSL keeps any type in its `ASN1_TYPE` or rejects it, for example with 106 or 137. In both places an INTEGER parameter that is empty or not minimally encoded fails with 62, and a NULL parameter with content fails with 148, where the pinned LibreSSL keeps the INTEGER and loads the certificate, and fails with 144 for that NULL. Not compared with the console.
